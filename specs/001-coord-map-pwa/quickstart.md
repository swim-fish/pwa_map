# Quickstart — Taiwan Coordinate Map (PWA)

**Feature**: `001-coord-map-pwa`
**Audience**: Engineers picking up the feature after `/speckit.plan`.

This quickstart is the shortest path from a fresh clone to:
(a) a running dev server with a working map + crosshair + coordinate readout,
and (b) a green test run (unit + E2E). It is NOT the implementation plan —
tasks will be emitted by `/speckit.tasks` — it is the environment setup
and smoke-test walkthrough the first implementor needs.

---

## 1. Prerequisites

- **Node.js**: 20.x LTS or 22.x LTS. Verify: `node --version`.
- **npm**: 10.x (bundled with Node 20/22). Verify: `npm --version`.
- **Git**: 2.40+ (already present in this repo).
- **Windows note**: all commands below are cross-platform; PowerShell and
  Bash both work. This project was bootstrapped on Windows 11 / PowerShell.
- No Docker, no backend, no database, no cloud credentials required.

---

## 2. One-time project bootstrap

Run from repo root (`C:\Users\hhhnr\source\repos\pwa_map`). These commands
only need to run on the first setup and whenever `package.json` changes.

```bash
# 1. Scaffold the Vite + Svelte + TypeScript project in-place
npm create vite@latest . -- --template svelte-ts
# (accept overwriting `package.json`; keep existing `.specify/`, `.claude/`,
#  `CLAUDE.md`, `specs/`, and `.git/` — they are orthogonal to the scaffold)

# 2. Install runtime deps
npm install maplibre-gl proj4 mgrs

# 3. Install dev deps
npm install -D vite-plugin-pwa workbox-window \
  vitest @vitest/ui jsdom \
  @playwright/test \
  prettier eslint typescript-eslint eslint-plugin-svelte \
  @types/proj4

# 4. Initialise Playwright (downloads headless browsers)
npx playwright install --with-deps

# 5. Copy the coordinate reference test vectors into the test fixtures
mkdir -p tests/unit/fixtures
cp ../atak_flutter_map/docs/coord-reference/test-vectors.json \
   tests/unit/fixtures/test-vectors.json

# 6. Record the pinned digest (see contracts/test-vectors.md §1)
sha256sum tests/unit/fixtures/test-vectors.json \
   > tests/unit/fixtures/vectors-digest.txt
```

After step 6, the repo should have:

```

public/
tests/unit/fixtures/test-vectors.json
tests/unit/fixtures/vectors-digest.txt
node_modules/
package.json
vite.config.ts
tsconfig.json
```

## 3. Configure the toolchain

### 3.1 `vite.config.ts`

Register the PWA plugin and wire the test command:

```ts
import { defineConfig } from 'vite';
import { svelte } from '@sveltejs/vite-plugin-svelte';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    svelte(),
    VitePWA({
      registerType: 'autoUpdate',
      manifest: { /* fill from src/pwa/manifest.ts */ },
      workbox: {
        runtimeCaching: [
          {
            urlPattern: /^https:\/\/tile\.openstreetmap\.org\/.*/,
            handler: 'StaleWhileRevalidate',
            options: { cacheName: 'osm-tiles', expiration: { maxAgeSeconds: 60 * 60 * 24 * 7 } },
          },
        ],
      },
    }),
  ],
  test: {
    environment: 'jsdom',
    globals: true,
  },
});
```

## 5. Dev-server smoke test (once the first components exist)

```bash
npm run dev
# → http://localhost:5173
```

Open the URL in Chrome/Edge. Expected first-visible state once the MVP
slice (US1) is complete:

- Full-viewport map tiled with OSM Standard, centered on Taipei 101.
- Crosshair reticle fixed at screen center, visible over imagery and
  light tiles.
- Below the map (or in a corner on mobile): one row of readout showing
  `緯度 25.033611° / 經度 121.564472°` (zh labels, DD values).
- OSM attribution `© OpenStreetMap contributors` in the bottom-right.

Drag the map — the readout numbers must update continuously, at least
10 refreshes per second on a mid-range laptop. If you see stutter during
pan, re-read `research.md R2` and profile before patching.

## 8. How to verify your coord math without launching the app

Drop a scratch file in at the repo root (not committed):

```ts
// scratch/taipei101.ts
import { initCoord, wgs84ToTwd97, wgs84ToMgrs, wgs84ToTaipower } from './src/coord';

initCoord();
const taipei = { kind: 'wgs84-dd' as const, lat: 25.033611, lon: 121.564472 };

console.log(wgs84ToTwd97(taipei));   // E ~306962.887, N ~2769619.124, zone 121
console.log(wgs84ToMgrs(taipei, 5)); // 51RUH5517069437 (joined)
console.log(wgs84ToTaipower(taipei)); // depends on TWD67 -> anchor table
```

Run with `npx tsx scratch/taipei101.ts`. The numbers must fall within
the tolerances documented in `contracts/test-vectors.md §5`.

## 9. Where to look when things break

| Symptom | Check |
|---|---|
| Coord values off by ~400 m | Proj4 entry for EPSG:3828 missing datum shift (research.md R4) |
| TM2 zone label wrong at `lon ~= 120°` | `src/coord/zone.ts` must use `>=` not `>` (§9 rule) |
| MGRS last digit off by one | Implementation is rounding; must truncate (reference §7) |
| Crosshair drifts during pan | MapView event wiring: use `move`/`moveend`, not `render` |
| Readout stutters | Debounce formatting (not computation); formatting is the hot path |
| PWA doesn't install offline | `vite-plugin-pwa` devOptions.enabled vs. `npm run preview` — offline install needs the prod build |
| Tests load wrong vectors | Check `vectors-digest.txt` matches the committed JSON |
